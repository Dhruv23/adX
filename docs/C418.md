# C418 Suite — Implementation Plan

Ambient / modern-classical generation suite for the adX engine, modeled on
C418's Minecraft-era sound (branch: `feature/experimentation-genres`).

## 1. Research Summary

C418 (Daniel Rosenfeld) builds sparse, warm, melancholic electronica around a
few signature devices:

- **Mallet/pluck timbres** — kalimba, pan drum ("Aria Math" is, in C418's own
  words, "a song full of Pan Drums and old synthesisers rhythmically dancing
  to ping pong delays"; Volume Beta used the Soniccouture Hang Drum Mk. 1 in
  "Aria Math" and "Dreiton"). Kontakt factory instruments (kalimba, pizzicato
  bass) and NI "The Giant" piano cover the acoustic side.
- **Warm analog-style pads** — Juno/Prophet-style slow-swelling pads with
  gentle low-pass filter movement ("Dreiton").
- **Space as an instrument** — long reverbs and tempo-synced (ping-pong)
  delays carry the arrangement; dry signals are rare.
- **Arpeggiated figures** — cascading 16th-note arpeggios over held chords,
  usually rising, sparse velocity.
- **Real synth hardware** — "Moog City 2" used actual Moogs; the takeaway for
  an additive engine is imperfect, rolled-off harmonic stacks, not brickwall
  digital brightness.

## 2. Mapping to the adX Engine

The engine is a 16-harmonic additive synth (`AudioEngine.cpp`) with
table-driven ADSR, per-track insert effects (Phase 5: `AudioEffect.h`), a
lock-free UI→audio event queue, and a master peak compressor.

### 2.1 Master Time-Based FX (Delay + Reverb)
- Add a **stereo ping-pong delay** and an **algorithmic reverb** (reuse
  `ReverbEffect`'s Freeverb core) as engine-owned master effects in
  `AudioEngine`, processed after the per-track bus mix and **before** the
  peak compressor.
- Buffers are pre-allocated in the `AudioEngine` constructor (Main Thread) —
  never in `process()`.
- Parameters (delay time ms, feedback, mix; reverb room/damp/mix) ride the
  existing `AudioEventType::ParameterChange` event with a new `EngineParam`
  id enum; a "MASTER FX" ImGui window edits them.
- Persistence: `[GLOBAL]` keys `DELAY=timeMs, feedback, mix` and
  `REVERB=room, damp, mix` in the `.adx` file.

### 2.2 Per-Voice Low-Pass Filter + LFO
- `Patch` gains `filterCutoffHz` (default 20000 = bypass), `filterLfoRateHz`,
  `filterLfoDepth` (0..1).
- `Voice` gains one-pole LPF state (`lpfZ`) and `lfoPhase`. Per sample:
  `cutoff = filterCutoffHz * (1 + depth * sin(lfoPhase))`, coefficient
  `a = 1 - exp(-2π·cutoff/fs)`, `y += a(x−y)` — cheap, no allocation, warm
  6 dB/oct rolloff exactly like slow analog pad movement in "Dreiton".

### 2.3 Patch Factory Library
- `PatchLibrary::Create(name)` (declared beside `Patch` in `AudioData.h`,
  implemented in `src/PatchLibrary.cpp`) returns fully-built patches with
  envelope tables generated at `kEngineSampleRate`:
  - **Kalimba** — harmonics {1.0, 0.2, 0, 0.4, 0, 0, 0, 0.4, …}; A 5 ms,
    D 300 ms, S 0.0, R 150 ms; light LPF ~7 kHz.
  - **Marimba** — fundamental + strong 4th harmonic (the wooden "double
    octave" partial); A 3 ms, D 250 ms, S 0.0, R 120 ms.
  - **Giant Piano** — 1/n harmonic rolloff over 8 partials, slight odd-partial
    emphasis; A 8 ms, D 900 ms, S 0.25, R 400 ms.
  - **Warm Pad** — full 1/n stack across all 16 partials; A 1200 ms, D 0,
    S 1.0, R 2500 ms; LPF 2.5 kHz with 0.1 Hz LFO at depth 0.4.
  - **Pizzicato** — fundamental + 2nd, fast rolloff; A 2 ms, D 100 ms, S 0.0,
    R 80 ms.
- Patch editor gets a library combo that loads a factory patch into the
  draft patch and dispatches a `PatchUpdate`.

### 2.4 Track-Level Arpeggiator
- `Track` gains a trivially-copyable `ArpSettings { mode (off/up/down/
  updown), rateBeats (default 0.25 = 16ths), octaves, gateLength }`.
- Implemented in `AudioEngine::process()` scheduling: for arp-enabled tracks,
  held/overlapping notes are NOT scheduled directly; instead each arp step on
  the `rateBeats` grid gathers the chord sounding at the step onset, sorts by
  pitch, and schedules one staccato NoteOn/NoteOff pair per step
  (`pattern index = stepIndex % patternLength`). Fully stateless per block —
  derived from the beat clock, so hot-reload/seek safe.
- Persistence: `ARP=mode, rateBeats, octaves, gate` line in `[TRACK]`;
  UI lives in the TRACK FX panel.

## 3. Order of Work
1. `Patch`/`Voice` filter fields + factory library (+ parser/UI).
2. Master delay & reverb in the engine + MASTER FX window + parser.
3. Arpeggiator scheduling + ARP UI + parser.
4. Ship a demo `c418_demo.adx` using Kalimba arps over a Warm Pad.
